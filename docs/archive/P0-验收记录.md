## 未验证项说明

`onKeyEvent` 在模拟器上完全不触发，即使 `AccessibilityServiceInfo.flags` 已确认包含
`FLAG_REQUEST_FILTER_KEY_EVENTS`（日志输出 `keyFilter=true`，`dumpsys accessibility`
显示 `capabilities=8`）。

原因是 `adb shell input keyevent` 注入的事件绕过了无障碍按键过滤层——注入事件直接进入
InputDispatcher，不经过 InputReader 的 `interceptKeyBeforeQueueing` 阶段。

结论：**按键拦截只能在真机用手按验证**，模拟器无法覆盖。P1 真机验收时必须手工确认以下三项：

1. 三键导航下按返回键 → 浮窗应保持，应用不应退出
2. 按 Home 键 → 应停留在当前应用
3. 连按音量下键 5 次 → 浮窗应立即消失

需要留意：Android 13+ 的返回手势走 `OnBackInvokedCallback`，不产生 KeyEvent，
手势返回必然拦不住，这部分只能交给 LockTask。

## 环境注意事项（本机特有，换机可忽略）

1. **aapt2 覆盖**：AGP 从 Maven 拉取的 aapt2 二进制在本机执行 `--emit-ids` 写文件时
   报「数据无效」，导致 `processDebugResources` 必然失败。已在 `gradle.properties`
   用 `android.aapt2FromMavenOverride` 指向 SDK build-tools 自带的 aapt2 解决。
2. **Gradle 分发**：`gradlew` 从 services.gradle.org 下载发行包会长时间阻塞，
   `gradle-wrapper.properties` 已改为腾讯云镜像。
3. **依赖仓库**：`settings.gradle.kts` 已将阿里云镜像置于官方源之前。

## 设计验证

- 区间结算式计时在熄屏/亮屏切换处未出现重复计或漏计。
- 惰性清零（熄屏只记时刻，亮屏才比较差值）正常工作，熄屏期间无任何定时器。
- 浮窗期间计时被正确冻结，休息的 20 秒未计入使用时长。
